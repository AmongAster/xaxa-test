# Шпаргалка по работе с Git-ветками (Как избегать конфликтов)

## 🛠 Часть 1. Создание новой ветки (Перед началом работы)
Всегда обновляйте локальный проект перед созданием новой ветки, чтобы не писать код поверх устаревшего.

```bash
# 1. Переключитесь на стабильную/целевую ветку (от которой будете наследоваться)
git checkout dev/workflow

# 2. Обновите список всех веток и изменений с GitHub
git fetch --all --prune

# 3. Подтяните самые последние коммиты из GitHub в вашу локальную ветку
git pull origin dev/workflow

# 4. Создайте свою новую рабочую ветку для текущей задачи
git checkout -b dev/my-new-feature
```

---

## 🚀 Часть 2. Перед отправкой кода на GitHub (Проверка на конфликты)
Проверяйте наличие конфликтов локально на своем компьютере, а не после открытия Pull Request.

```bash
# 1. Сохраните и закоммитьте всю вашу текущую работу в вашей ветке (например, dev/h)
git add .
git commit -m "feat: complete my work"

# 2. Скачайте свежие изменения с сервера, которые могли залить коллеги
git fetch --all --prune

# 3. Попробуйте «влить» целевую ветку сервера в свою локальную рабочую ветку
git merge origin/dev/workflow
```

### Что делать дальше:
* **Вариант А (Конфликтов нет):** Git напишет `Already up to date` или `Merge made by...`. Можно смело отправлять код на GitHub:
  ```bash
  git push origin dev/h
  ```
* **Вариант Б (Появился конфликт):** Git выведет список конфликтующих файлов в консоли. Ваша IDE подсветит их красным. Откройте эти файлы, выберите правильные строчки кода, сохраните, а затем сделайте финальный фиксирующий коммит:
  ```bash
  git add .
  git commit -m "fix: resolve merge conflicts"
  git push origin dev/h
  ```
